1はじめに

キーワードを入れると、競合サイトを調べたうえで数千文字のSEO記事を書き上げるツールです。構成案づくり、本文執筆、校正、メタディスクリプションの生成までを通しで行います。画像は姉妹ツールの imager で作ります。

入るには

seo.lishinc.co.jp を開くと、Googleのログイン画面が出ます。@lishinc.com のアカウントを選べば入れます。個人のGmailアカウントでは入れません。

ブラウザに複数のGoogleアカウントでログインしている場合、別のアカウントが選ばれて弾かれることがあります。その場合はシークレットウィンドウで開き直すか、アカウントを切り替えてください。

アクセスできないとき

@lishinc.com のアカウントで入れない場合は、吉田までご連絡ください。アクセス権の設定を確認します。

使うときに知っておくこと

  • 記事を1本作るのに10〜20分かかります。ブラウザのタブは閉じずに待ってください。
  • 生成にはAIの利用料がかかります。テストで何本も回すのは避けてください。
  • https:// でアクセスしてください。http:// ではつながりません。

2記事を作る

動作確認済み

基本の流れです。キーワードを1つ入れて、構成案を作り、執筆を始める。この3手で1本仕上がります。

  1. キーワードを入力する

    トップの入力欄に、記事にしたいキーワードを入れます。「ドライヘッドスパ 効果」のように、単語を空白で区切った検索キーワードの形で入れてください。

  2. 構成案を作る

    「構成案作成」を押すと、競合サイトを調べたうえで見出し構成を組み立てます。ここで数分かかります。

    できた構成案は、見出しの追加・削除・並べ替えができます。内容に違和感があれば、この段階で直しておくと本文の質が上がります。

  3. 執筆を始める

    「執筆開始（Ver.1）」を押すと、セクションを順番に書いていきます。画面に進捗が出るので、そのまま待ってください。

    途中で「構成案にエラーが見つかりました。自動修正を開始します」と出ることがありますが、そのまま進んで問題ありません。自動で直して続行します。

  4. できあがりを確認する

    完了すると、プレビュー・HTMLコード・編集・画像生成のタブが出ます。文字数と目標文字数が表示されるので、目標に届いているか確認してください。

完了表示のあと、3分ほど画面が止まります

「記事生成完了」と出てから結果が表示されるまで、くるくる回ったまま2〜3分待たされることがあります。故障ではないので、閉じずに待ってください。

目安

実際に「ドライヘッドスパ 効果」で作ったときは、7セクション・約4,900文字の記事ができました。競合サイトの調査は9件すべて成功しています。

画像を作る

記事本文を imager.lishinc.co.jp に貼り付けると、見出しごとに画像を生成して差し込んでくれます。

記事と画像の受け渡しは手動です

2つのツールは独立しているので、記事を自動で imager に送る機能はありません。記事のHTMLをコピーして、imager に貼り付けてください。imager の画面表示は現在英語です。

4スプレッドシート連携

セットアップが必要・未検証

キーワードをスプレッドシートに並べておき、印をつけた行だけをまとめて記事化する使い方ができます。書き上がるとタイトルやメタディスクリプションがシートに戻ってきます。

この章はまだ本番で動かせません

使うには第5章の管理者セットアップが必要で、そのセットアップはまだ実施していません。手順はツールの仕様書に基づいて書いていますが、実機での確認はこれからです。

シートの形

A列からG列まで、決まった並びで用意します。1行目は見出し行です。

ABCDEFG
No.KW編集用URLSlugタイトル公開用URLメタディスク
1ドライヘッドスパ 効果1自動自動自動
2ドライヘッドスパ 頻度1自動自動自動
3ドライヘッドスパ 料金

C列に印のある1・2行目だけが処理されます。3行目は対象外です。

列入れるもの誰が入れるか
A連番自分で入力
B記事にしたいキーワード自分で入力
C処理したい行に 1 を入力（全角の １ でも可）自分で入力 → 処理後はCMSの編集用URLに上書きされます
D記事のURL用文字列（スラッグ）自動
E記事タイトル自動
F公開後のURL自分で入力。他の記事から内部リンクを張るために使われます
Gメタディスクリプション自動

使う流れ

  1. シートを用意する

    上の形でスプレッドシートを作り、B列にキーワード、記事にしたい行のC列に 1 を入れます。すでに公開済みの記事があれば、F列にそのURLを入れておくと内部リンクに使われます。

  2. シートを共有する

    ツールがシートを読み書きできるよう、サービスアカウントに編集者として共有します。共有先のアドレスは管理者に確認してください。

  3. スプシモードをオンにする

    キーワード入力画面の「スプシモード」トグルをオンにすると、印をつけたキーワードの一覧が表示されます。

  4. まとめて実行する

    処理したいキーワードを選んで一括処理を始めます。記事が書き上がってCMSに投稿されると、C・D・E・G列が自動で埋まります。

シートへの書き戻しにはCMS投稿が必要です

C〜G列が自動更新されるのは、記事がCMSに投稿されたときです。現在は投稿機能をすべて停止しているため、書き戻しまでは動きません（第7章）。キーワードの読み取りと記事生成までは、セットアップが済めば使えます。

5管理者向けセットアップ

未実施

スプレッドシート連携を使えるようにするための作業です。GCPの操作を含むので、担当者の方は読み飛ばして構いません。

  1. Google Sheets API を有効にする

    GCPコンソールで、プロジェクト lish-seo-agent の Google Sheets API を有効化します。

  2. サービスアカウントを作る

    名前は sheets-api-access。ロールの付与はスキップして構いません。

  3. JSONキーを発行する

    作成したサービスアカウントのキーをJSON形式で発行し、ダウンロードします。このファイルは共有せず、手元で保管してください。

  4. Secret Manager に登録する

    シークレット名は GOOGLE_SERVICE_ACCOUNT_JSON。値はJSONキーの中身です。

  5. backend-server に環境変数を渡す

    シークレット参照で追加します。シークレット名と環境変数名が違うので注意してください。

    環境変数名値
    GOOGLE_APPLICATION_CREDENTIALS_JSONシークレット GOOGLE_SERVICE_ACCOUNT_JSON を参照
    SPREADSHEET_IDシートURLの /d/ と /edit の間の文字列
  6. シートを共有する

    対象のスプレッドシートを、次のアドレスに編集者として共有します。

    sheets-api-access@lish-seo-agent.iam.gserviceaccount.com
  7. クライアントごとのシートIDを設定する

    マルチクライアント運用では、クライアント設定の spreadsheetId が優先され、SPREADSHEET_ID はその予備として使われます。現在はすべてのクライアントで spreadsheetId が空のため、使うクライアントに個別に設定が必要です。

認証まわりの未確認事項

現在 backend-server には GOOGLE_APPLICATION_CREDENTIALS_JSON が渡っていません。手順4〜5を実施するか、Cloud Runのサービスアカウント自体にSheetsの権限を与えるかで動かす形になりますが、後者で動くかは未検証です。

6困ったときは

ログイン画面から先に進めない

@lishinc.com 以外のアカウントが選ばれている可能性があります。シークレットウィンドウで開き直してください。それでも入れない場合は吉田までご連絡ください。

ページが開かない

URLが http:// になっていないか確認してください。https:// でないとつながりません。

「記事生成完了」から先に進まない

完了表示のあと2〜3分、画面が止まったように見えることがあります。既知の挙動なので、そのまま待ってください。

「投稿先が未選択です」と出る

現在CMSへの投稿機能を停止しているため、この警告は出たままになります。記事の生成自体には影響しません。ダウンロードやコピーで取り出してください。

「構成案にエラーが見つかりました」と出た

自動で修正して続行します。そのまま待って問題ありません。

タイトルが長すぎる／不自然につながっている

見出しをそのままつなげたようなタイトルが出ることがあります。既知の問題として調査中です。タイトルは手直しして使ってください。

それでも解決しないとき

状況を伝えるときは、次の情報があると原因を追いやすくなります。

  • 入力したキーワード
  • どの操作で止まったか（構成案作成／執筆開始／保存）
  • 画面に出ているエラー文言
  • 可能であれば、ブラウザの検証ツール（F12）のConsoleタブに出ている赤い行
